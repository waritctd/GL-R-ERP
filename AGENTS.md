# GL&R ERP

HR and Sales/CRM portal for GL&R, growing into an ERP. The UI is Thai. **This repository is public.**

## Stack

- **Language / Runtime**: Java 21 (`backend/`), JavaScript on Node 22 (`frontend/`, no TypeScript)
- **Framework**: Spring Boot 4 with plain JDBC and Flyway on PostgreSQL 16; React 18, Vite 8, Tailwind 4
- **Key dependencies**: TanStack Query, react-hook-form with zod, Apache POI and LibreOffice for documents, Vitest, Playwright
- **Package manager**: Maven wrapper (`backend/mvnw`), npm (`frontend/`)
- **Hosting**: Vercel builds the frontend from `main`. The backend image and Postgres run on the office server (`ops/onprem/README.md`)

## Build approach

**Tracer Bullet**: each change is built end to end through database, API and screen, thin but working, and shown running before the next one starts. Set in `docs/scope/index.md`, with the workflow level (Beta: after develop, check verify, then test).

## Commands

```bash
# Install
cd frontend && npm install

# Dev server, mock mode (no backend, no database)
cd frontend && VITE_USE_MOCKS=true npm run dev          # http://localhost:5174

# Dev server, real backend with demo data
docker compose up -d db
cd backend && SPRING_PROFILES_ACTIVE=demo SERVER_SESSION_COOKIE_SECURE=false APP_MAIL_PROVIDER=log ./mvnw spring-boot:run
cd frontend && npm run dev

# Build
cd backend && ./mvnw -DskipTests package
cd frontend && npm run build

# Test (targeted, see Rules)
cd backend && ./mvnw -Dtest.fork.count=1 -Dtest=<ClassName> test
cd frontend && npm run lint && npx vitest run <path>
```

## Specs

Stored in `docs/specs/`. Format: `docs/specs/NNNN-title.md`. Past decisions are in `docs/decisions/`, the sales flow in `docs/sales-workflow.md`, version rules in `docs/versioning.md`.

## Rules

- **Public repo.** Never commit customer or employee data, real document numbers, credentials, server settings or licensed fonts. Fixtures, screenshots and templates use made up data.
- **The backend decides permissions.** The mock API mirrors endpoints and shapes only. Check every access rule against the Java service.
- **An API change touches both sides.** Add the method to `hrApi.js` and `mockApi.js`, then regenerate the digests in `docs/api/`.
- **Migrations are forward only.** Never edit an applied one. Take the next number after the highest on `origin/develop`.
- **Money is `BigDecimal` with `HALF_UP`. Time is `Asia/Bangkok`.** The UI shows Buddhist era years, stored values stay ISO.
- **Sales screens say งาน, never ดีล.** Design for a sales rep on a phone in a hurry: few taps, never stuck.
- **Reuse before you write.** Shared UI is in `frontend/src/components/common`, access policies in the backend `auth` package. Make the smallest change that fully solves the task.
- **Tests come after the code, and stay few.** No test first pass. Revise an existing test before adding one, and delete stale ones.
- **Run targeted tests locally, never the full backend suite.** CI runs everything on each push to `develop` and `main`, and a picked subset on pull requests.
- **One heavy background job at a time** (build, test run, review). Many sessions share one machine.

## Workflow

- **Branches**: `develop` collects finished work. `main` is production. Work in your own branch or worktree cut from `origin/develop`, and rebase onto it before you push.
- **Before you push**: show the slice working in the real app, run a code review at medium effort, fix every finding, rerun the targeted tests. Then push to `develop`. Never force push `develop` or `main`.
- **Commits**: `type(scope): what changed`, as in the git log. No `Co-Authored-By` trailer and no generated by footer, in commits or pull requests.
- **Releases belong to the deployer session only.** No other session pushes to `main`, builds a backend image, touches the server, tags a release or sends release mail. Stop at `develop` and hand over the SHA, saying patch or minor, and whether it holds backend changes or a migration.
- **The deployer** releases only when all three CI workflows are green on that exact SHA, walks the change in the real UI before any mail goes out, and follows `docs/versioning.md` and `ops/onprem/README.md`.
- **Production data is read only** unless the owner approves the exact change.
